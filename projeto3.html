Debian "lab01"
UFW + Fail2ban do zero

VM: 192.168.56.48 SO: Debian Forky (6.19.10) Host: Linux Mint 22.1

Nova VM Debian criada do zero. Objetivo: configurar hostname, instalar UFW e Fail2ban, corrigir erros reais no caminho e documentar cada decisão tomada no terminal.

Identificação da VM no lab. O erro de resolução apareceu porque /etc/hosts ainda não tinha o novo nome — corrigido antes do reboot.

3. Instalação do UFW — erro 404 e correção
Primeira tentativa de instalar o UFW falhou. O repositório tinha um pacote desatualizado. Solução: atualizar sources e depois modernizá-los.
debian@lab01
debian@lab01:~$sudo apt install ufw -y
Erro: Falhou ao obter libnfnetlink0_1.0.2-3+b1 404 Not Found
debian@lab01:~$sudo apt-get update
Erro: Couldn't find the start of the patch series
N: Execute 'apt modernize-sources' para fazer isso.
debian@lab01:~$sudo apt modernize-sources
Reescrever 1 fontes? [S/n]s
Writing /etc/apt/sources.list.d/debian.sources
debian@lab01:~$sudo apt-get update
Atingido — listas atualizadas com sucesso
debian@lab01:~$sudo apt install ufw -y
ufw instalado com sucesso
⚠
O que aconteceuO sources.list estava no formato antigo. O Debian Forky usa o novo formato .sources. O comando apt modernize-sources migra automaticamente.
4. Configuração do UFW — regra duplicada e correção
Adicionei allow ssh e depois allow 22 separado — resultado: regra duplicada. Aprendi a identificar duplicatas com ufw status numbered e a resetar quando necessário.
debian@lab01
debian@lab01:~$sudo ufw allow ssh
Rules updated / Rules updated (v6)
debian@lab01:~$sudo ufw allow 22
# resultado: regra duplicada no status
debian@lab01:~$sudo ufw reset
Resetting all rules to installed defaults.
debian@lab01:~$sudo ufw allow ssh
debian@lab01:~$sudo ufw enable
Firewall is active and enabled on system startup
debian@lab01:~$sudo ufw status numbered
[ 1] 22/tcp ALLOW IN Anywhere
[ 2] 22/tcp (v6) ALLOW IN Anywhere (v6)
ℹ
Liçãoallow ssh e allow 22 fazem a mesma coisa. Use apenas um. O ufw reset limpa tudo e permite recomeçar do zero.
5. Instalação do Fail2ban — erro de comando
Tentei usar install diretamente. Não é o comando correto para instalar pacotes — esse é um erro comum de quem está aprendendo Linux.
debian@lab01
debian@lab01:~$sudo install fail2ban -y
install: opção inválida -- "y"
debian@lab01:~$sudo apt install fail2ban -y
fail2ban instalado com sucesso
⚠
Confusão comuminstall sozinho é um utilitário para copiar arquivos. Para instalar pacotes no Debian/Ubuntu, sempre use apt install.
6. Fail2ban rodando — jail sshd ativo
Serviço iniciado automaticamente após instalação. Jail padrão do SSH já ativo sem configuração adicional.

O que aprendi nessa sessão
01
apt modernize-sources — O Debian Forky usa o novo formato .sources. Se o update der erro de "patch series", rode esse comando antes de tentar instalar qualquer coisa.
02
Não duplicar regras no UFW — allow ssh já é suficiente. Adicionar allow 22 depois cria regra duplicada. Usar ufw status numbered para inspecionar antes de ativar.
03
ufw deny sem planejamento trava o acesso — Rodei deny 22 sem pensar. Se o firewall estivesse ativo naquele momento, teria perdido o acesso SSH à VM.
04
install ≠ apt install — sudo install é um utilitário do sistema para copiar arquivos. Para instalar pacotes no Debian, o comando correto é sempre sudo apt install.
05
ufw reset — Quando as regras ficam bagunçadas, o jeito mais rápido de limpar é ufw reset e recomeçar do zero. Mais eficiente que tentar deletar regra por regra.
